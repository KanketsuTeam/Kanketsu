# 🧠 核心概念

本文档介绍 Kanketsu 背后的核心概念。

理解这些概念后，你将能自然而然地设计 CLI 应用，而无需死记硬背 API。

---

# 🌳 命令树

每个 Kanketsu 应用都组织为一棵**命令树**。

例如：

```text
git
├── add
├── commit
│   └── amend
└── push
```

树中的每个节点代表一个命令。


一个命令可以包含：

* 📦 子命令
* ⚙️ 选项
* ▶️ 动作（Action）

嵌套命令就是同一棵树中嵌套的节点。

---

# 📦 命令

命令代表一个单一操作。

例如：

```text
build
test
deploy
copy
commit
```

每个命令都有明确的职责。

一个命令定义了：

* 🏷️ 名称
* ⚙️ 可用的选项
* 📦 子命令
* ▶️ 执行时的行为

命令本身不执行解析，它们只描述应用的结构。

---

# ⚙️ 选项

选项用于修改命令的行为。

例如：

```text
--file config.yml
-v
--force
```

Kanketsu 同时支持短选项、长选项和全局选项、可选值、必选值和默认值。

解析完成后，选项值会成为命令上下文的一部分。

---

# 📍 位置参数

未被解析为选项的参数会变为**位置参数**。

例如：

```text
copy source.txt destination.txt
```

其中：

* 📦 `copy` 是命令。
* 📍 `source.txt` 是第一个位置参数。
* 📍 `destination.txt` 是第二个位置参数。

位置参数保持其原始顺序。

---

# 🧾 命令上下文

当命令被执行时，Kanketsu 会创建一个**命令上下文**。

上下文中包含命令执行所需的一切信息。

典型信息包括：

* ⚙️ 解析后的选项
* 📍 位置参数
* 📦 匹配到的命令
* 📝 执行元数据

命令动作不访问全局状态，而是通过上下文对象接收所有必要信息。

这使得命令更容易测试，也更容易推理。

---

# 🔍 解析

解析器将用户输入转换为结构化数据。

从概念上讲，流程如下：

```text
⌨️ 用户输入
        │
        ▼
🔍 参数解析器
        │
        ▼
🌳 命令解析
        │
        ▼
🧾 命令上下文
        │
        ▼
▶️ 命令动作
```

应用代码只与最终结果——命令上下文——交互。

在此之前的一切都由框架处理。

---

# ▶️ 执行

Kanketsu 应用每次遵循相同的执行流程：

```text
⌨️ 用户输入
        │
        ▼
🔍 解析参数
        │
        ▼
🌳 解析命令
        │
        ▼
🧾 创建上下文
        │
        ▼
▶️ 执行动作
```

这种可预测的流程让命令执行易于理解和调试。

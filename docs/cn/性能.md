# ⚡ 性能

Kanketsu 的设计目标是**可预测的性能**、**极短的启动时间**和**出色的 GraalVM Native Image 兼容性**。

Kanketsu 不依赖反射、注解处理或运行时扫描，而是采用显式的命令注册方式，并使用轻量级数据结构进行命令解析。

以下基准测试展示了当前实现的性能特征。

---

# 🚀 Native Image 启动时间

Kanketsu 的主要目标之一，是为 GraalVM Native Image 应用提供出色的启动性能。

## 实测结果

```text
$ time ./KanketsuTest

HI

real    0m0.006s
user    0m0.000s
sys     0m0.006s
```

### 结果解读

| 指标     |  结果   | 说明                                                                  |
| :------- | :-----: | :-------------------------------------------------------------------- |
| **real** | **6 ms** | 总墙钟执行时间                                                        |
| **user** | **0 ms** | 被 Linux `time` 工具舍入为零（实际执行时间低于可测量精度）            |
| **sys**  | **6 ms** | 操作系统和虚拟化开销                                                  |

在 WSL2 环境下使用 GraalVM Native Image 测得启动时间约为 **6 毫秒**。

# 💡 Kanketsu 为什么快？

Kanketsu 的性能优势直接源于其架构设计。

## 🚫 零反射

命令注册和执行从不依赖运行时反射。

这消除了反射开销，同时让 GraalVM Native Image 编译变得简单直接。

---

## 🌳 轻量级命令树

命令以轻量级的树形结构存储。

解析如下命令：

```text
git remote add
```

只需遍历这棵树即可。

---

## 📝 轻量级解析器

解析器使用直接的字符串处理实现。

支持的功能包括：

* 短选项（`-v`）
* 组合短选项（`-abc`）
* 附加值（`-fconfig.yml`）
* 长选项（`--file`）
* 长选项赋值（`--file=config.yml`）
* 选项终止符（`--`）

不涉及解析器生成器或外部库。

---

## 📦 零传递依赖

核心模块不引入任何传递依赖。

这最大限度地减少了：

* 启动开销
* 类加载时间
* 依赖体积

---

## 🏗 优先 AOT

Kanketsu 从一开始就为 GraalVM Native Image 而设计。

核心模块避免：

* 反射
* 运行时扫描
* 注解处理

因此，无需额外配置反射文件。

# 📄 基准测试源码

## Native Image 启动测试

### Simple.java

```java
import core.io.github.kanketsuteam.kanketsu.CLI;

public class Simple {
    public static void main(String[] args) {
        CLI cli = CLIHolder.cli;
        cli.execute("hi");
    }
}
```

### CLIHolder.java

```java
import core.io.github.kanketsuteam.kanketsu.CLI;

public class CLIHolder {

    public static CLI cli = CLI.builder()
            .command("hi", hi -> hi
                    .action(ctx -> System.out.println("HI")))
            .build();

}
```

命令树在类加载期间初始化，以便基准测试只测量应用启动和执行的时间。

# 📦 模块

Kanketsu 由一组相互独立的模块构建而成。

Kanketsu 不会把所有功能塞进一个框架，而是保持核心的专注，让额外功能可以独立演进。

这种模块化架构让应用保持轻量，同时让生态易于扩展。

---

# 🏛 设计哲学

模块系统体现了 Kanketsu 的核心原则之一：

> **模块化优于单体**

核心只应提供创建命令行应用所需的基础构建块。

其他一切都属于可选模块。

这一理念让核心保持：

* 🚀 轻量
* 🔍 可预测
* 🧩 易于理解
* 🏗 对 GraalVM Native Image 友好

某个功能不被包含，不是因为它不重要——而是因为它属于别的地方。

---

# 📦 核心模块

**工件**

```text
kanketsu-core
```

核心模块是 Kanketsu 的心脏。

它提供了构建命令行应用所需的一切，包括：

* 🌳 命令注册
* 🧭 命令路由
* ⚙️ 参数解析
* 📝 选项解析
* ▶️ 命令执行
* 🆘 内置帮助生成

核心模块**零传递依赖**，并有意识地避免：

* 反射
* 运行时扫描
* 注解处理

对大多数应用而言，**核心模块是唯一必需的依赖**。

---

# 💻 REPL 模块

**工件**

```text
kanketsu-repl
```

REPL 模块基于 Kanketsu 提供了交互式命令行环境。

典型功能包括：

* 交互式 Shell
* Tab 补全
* 内置的通用编码日志实现
* 快速创建一个终端实例

REPL 模块依赖 JLine，完全可选。

直接从操作系统执行命令的应用通常不需要此模块。

# 📄 JSON 模块

**工件**

```text
kanketsu-json
```

JSON 模块增加了从命令行选项或位置参数直接解析 JSON 输入的能力。

它提供了一个 `TypeConverter` 实现，能自动检测输入是：

* JSON 字符串（以 `{` 或 `[` 开头）
* 文件路径（读取文件内容并解析为 JSON）

该模块与 Kanketsu 的 SPI 无缝集成，让命令能接收强类型的 JSON 结构（`JsonObject`、`JsonArray`），无需手动解析或使用易出错的反射。

**核心特性：**

* 自动识别 JSON 字符串还是文件路径
* 精确定位无效 JSON 的错误位置
* 零反射——完全兼容 GraalVM Native Image
* 较小的依赖体积（使用 `json-simple`，无额外传递依赖）

**使用示例：**

```java
CLI.builder()
    .converter(JsonTypeConverter.INSTANCE)
    .command("parse", cmd -> cmd
        .option("config", opt -> opt
            .hasArg(true)
            .converter(Converters.STRING)
            .required(true))
        .action(ctx -> {
            JsonObject config = ctx.getOptionValueAs("config", JsonObject.class);
            String host = (String) config.get("host");
            System.out.println("Host: " + host);
        })
    )
    .build();
```

**适用场景：**

* CLI 需要接收结构化配置（如部署规格、服务定义）
* 希望同时支持内联 JSON 和基于文件的输入
* 需要对无效 JSON 提供精确的错误反馈

**Maven 依赖：**

```xml
<dependency>
    <groupId>io.github.kanketsuteam</groupId>
    <artifactId>kanketsu-json</artifactId>
    <version>2.1.1</version>
</dependency>
```

# 🔮 未来模块

Kanketsu 有意将许多功能放在核心之外。

潜在的生态模块包括：

* 📄 YAML 配置支持
* 🔌 第三方集成

这些模块不属于核心，是因为它们解决的是特定的集成问题，而非通用的 CLI 问题。

将它们分离出来，让生态可以持续发展，而不会增加框架本身的复杂度。

---

# 🎯 模块选择

只选择你应用需要的模块。

典型的 CLI 应用：

```text
kanketsu-core
```

交互式 Shell：

```text
kanketsu-core
+ kanketsu-repl
```

需要 JSON 输入支持：

```text
kanketsu-core
+ kanketsu-json
```

未来模块可以独立添加，不影响已有应用。

---

# 💡 为什么模块化？

保持核心小巧带来了诸多好处：

* 📦 更小的依赖体积
* ⚡ 更快的启动速度
* 🧹 更简单的维护
* 🔄 模块可独立演进
* 🏗 更好的 AOT 兼容性

Kanketsu 的目标不是成为一个单体框架，而是为一个不断增长的生态提供稳定的基础。

# 🔧 Shell 补全模块

**工件**

```text
kanketsu-completion-maven-plugin
```

Shell 补全模块是一个 **Maven 插件**，能根据你的命令树定义为基于 Kanketsu 的 CLI 应用自动生成 Shell 补全脚本（Bash / Zsh / Fish）——**无需手动维护**。

## 📦 为什么需要这个模块？

手动维护补全脚本很容易让脚本与代码脱节。本插件在构建时自省你现有的 `CLI` 实例，生成准确、最新的补全脚本。

主要优势：

- **零手动工作**——补全从你的命令树自动生成。
- **多 Shell 支持**——Bash、Zsh 和 Fish（PowerShell 支持计划中）。
- **上下文感知**——根据当前命令路径补全命令、子命令和选项。
- **原生镜像友好**——无需运行时反射；补全在 Maven 构建期间生成。

## 📥 安装

将插件添加到 `pom.xml` 的 `<plugins>` 部分：

```xml
<plugin>
    <groupId>io.github.kanketsuteam</groupId>
    <artifactId>kanketsu-completion-maven-plugin</artifactId>
    <version>2.1.1</version>
    <executions>
        <execution>
            <id>generate-completion</id>
            <phase>package</phase>
            <goals>
                <goal>generate</goal>
            </goals>
        </execution>
    </executions>
</plugin>
```

## ⚙️ 配置参数

| 参数          | 类型     | 必填 | 默认值                                     | 说明                                                              |
|:--------------|:---------|:-----|:-------------------------------------------|:------------------------------------------------------------------|
| `cliClass`    | `String` | 是   | —                                          | 持有静态 `CLI` 实例的类的全限定名。                               |
| `cliField`    | `String` | 否   | `cli`                                      | 持有 `CLI` 实例的静态字段名称。                                   |
| `shell`       | `String` | 否   | `bash`                                     | 目标 Shell：`bash`、`zsh` 或 `fish`。                             |
| `commandName` | `String` | 否   | `artifactId`                               | CLI 命令名称（补全脚本中使用的名称）。                            |
| `outputFile`  | `File`   | 否   | `target/${artifactId}_completion.${shell}` | 生成脚本的输出路径。                                              |

### 配置示例

```xml
<plugin>
    <groupId>io.github.kanketsuteam</groupId>
    <artifactId>kanketsu-completion-maven-plugin</artifactId>
    <version>2.1.1</version>
    <executions>
        <execution>
            <id>generate-completion</id>
            <phase>package</phase>
            <goals>
                <goal>generate</goal>
            </goals>
            <configuration>
                <cliClass>com.example.yourapp.CLIHolder</cliClass>
                <cliField>cli</cliField>
                <shell>bash</shell>
                <commandName>yourapp</commandName>
            </configuration>
        </execution>
    </executions>
</plugin>
```

## 📝 前置条件

1. **CLI 实例必须定义在 `public static` 字段中**，详见[原生镜像指南](原生镜像.md)。例如：
   ```java
   public class CLIHolder {
       public static CLI cli = CLI.builder()
           .command("hello", cmd -> cmd.action(...))
           // ...
           .build();
   }
   ```
2. 项目必须使用 **Java 25+** 构建。
3. `kanketsu-core` JAR 必须在 classpath 中可用。

## 🚀 使用方法

### 生成脚本

正常执行 Maven——脚本会在 `package` 阶段自动生成：

```bash
mvn clean package
```

生成的脚本位于 `target/yourapp_completion.bash`（或 `.zsh` / `.fish`，取决于 `shell` 配置）。

### 加载脚本

- **Bash / Zsh**
  ```bash
  source /path/to/yourapp_completion.bash
  ```
  如需永久生效，将 `source` 命令添加到 `~/.bashrc` 或 `~/.zshrc`。

- **Fish**
  ```bash
  source /path/to/yourapp_completion.fish
  ```
  或复制到 `~/.config/fish/completions/` 以自动加载。

- **Windows Git Bash**
  同样的命令在 Git Bash 中有效。使用 POSIX 风格路径：
  ```bash
  source /d/CLI/yourapp/target/yourapp_completion.bash
  ```

### 测试

加载脚本后，输入命令名并按下 **Tab**：

```bash
$ yourapp <Tab><Tab>
api   auth   issue   pr   repo   version

$ yourapp issue <Tab><Tab>
list   view   create   close

$ yourapp issue list -<Tab>
--repo   -r    --state   -s    --limit   -l    --assignee   -a
```

## 🧩 工作原理

1. **构建时自省**——Maven 插件在构建时通过反射加载你的 `CLI` 实例。
2. **命令树遍历**——遍历整棵命令树，收集子命令和选项。
3. **脚本生成**——生成纯 Shell 脚本，使用基于 `case` 的分发逻辑实现上下文感知补全。
4. **零运行时开销**——生成的脚本完全在 Shell 中运行，应用本身不会被调用来完成补全。

## 🐚 支持的 Shell

| Shell       | 状态   | 说明                                 |
|:------------|:-------|:-------------------------------------|
| Bash        | 完整   | 包含上下文感知补全。                 |
| Zsh         | 完整   | 原生 `compadd` 支持。                |
| Fish        | 完整   | 原生 `complete` 命令支持。           |
| PowerShell  | 未支持 | 可能在未来版本中添加。               |

## 💡 实用技巧

### 多 Shell 支持

你可以通过添加多个 execution 来生成多种 Shell 的补全脚本：

```xml
<execution>
    <id>generate-bash</id>
    <configuration><shell>bash</shell></configuration>
</execution>
<execution>
    <id>generate-zsh</id>
    <configuration><shell>zsh</shell></configuration>
</execution>
<execution>
    <id>generate-fish</id>
    <configuration><shell>fish</shell></configuration>
</execution>
```

### 分发补全脚本

打包 CLI 工具时，可以将生成的补全脚本包含在分发包或包管理器（如 Homebrew、APT）中。这样用户只需一条命令即可启用补全。

### Windows 用户

在 Windows 上，生成的 Bash 脚本适用于：
- **Git Bash**（推荐）
- **WSL**（Windows Subsystem for Linux）
- **Cygwin**

如需原生 PowerShell 补全，可考虑使用包装脚本或等待未来支持。
